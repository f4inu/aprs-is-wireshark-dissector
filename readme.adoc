= Wireshark APRS-IS lua dissector

This is a lua APRS-IS parser for Wireshark. It decodes the APRS-IS TCP
framing (one APRS frame per `\r\n`-terminated line, lines reassembled
across TCP segments) and, within each frame:

* source / destination (with SSID split), digipeater path (per element,
  with the "heard directly" `*` flag), q-construct with meaning
* login lines (`user … pass … vers …`), server chatter (`# aprsc …`,
  `# logresp …`) and blank-line heartbeats
* information-field types: position (plain, compressed, timestamped),
  status, messages (multi-addressee, ack/rej/multi-ack, BLN/NWS
  bulletins), objects (base-91 timestamps, live/killed), items and DF
  items with overlays, Mic-E (destination-call message bits and
  latitude digits, manufacturer type/version, NNNN} altitude), weather
  reports (and the post-position `_` extension), telemetry (T#, T=,
  T!, T^, PARM/UNIT/EQNS labels, `|…|` comment extension), third-party
  traffic (decoded recursively), station capabilities (XML), raw
  NMEA/GPS, positionless course/speed, query, user-defined data,
  Maidenhead beacons
* comment extras: `/A=` altitude, `FFF.FFFMHz` frequency, PHG, DFS,
  `!DAO!`, symbol table/code resolved to symbol names, decimal
  latitude/longitude fields

Destination callsigns such as `TCPIP*` are identified from
http://www.aprs.org/aprs11/tocalls.txt, now
https://github.com/aprsorg/aprs-deviceid[aprs-deviceid] (not yet
annotated in the tree -- see todo).

== Installation

Copy `wireshark_aprsis.lua` to the personal lua plugin folder. To find where it is, select "Help/About Wireshark" in Wireshark, and then in the 'Folders' tab the 'Personal Lua Plugins' folder is listed.

On Linux and some unices, this should do the trick:
[,console]
----
$ cp wireshark_aprsis.lua ~/.local/lib/wireshark/plugins/
----

Note: Debian/Ubuntu ship an AppArmor profile for tshark that may refuse
to read lua plugins from your home directory; the Wireshark GUI is not
affected.

== Usage

Both the client port (10152) and the standard APRS-IS port (14580) are
registered, so decoding is automatic in both directions. For payloads
on any other port, right-click the tcp payload in Wireshark, select
"Decode As" and map it to APRS-IS.

You can now use display filters as usual with any of the packet fields as explained on https://www.wireshark.org/docs/wsug_html_chunked/ChWorkBuildDisplayFilterSection.html[the documentation].

* `aprsis.source == "F4INU"` : filter on source callsign
* `aprsis.destination_callsign contains "IGATE"` : destination callsign
* `aprsis.digipeater.callsign == "WIDE1-1"` : seen through a radio path element
* `aprsis.info_field.type_decoded contains "Weather"` : weather reports
* `aprsis.q_construct.code == "qAR"` : igated from RF
* `aprsis.lat_deg > 45 && aprsis.freq exists` : northern stations naming a frequency

== Test

If you want to receive an APRS-IS unfiltered full feed for testing purposes, the following wil do:

[source,console]
----
$ echo "user foo pass -1 vers telnet" | nc euro.aprs2.net 10152
# aprsc 2.1.19-g730c5c0
# logresp foo unverified, server T2LAUSITZ
KN6ABC-R>APDG03,TCPIP*,qAC,KN6WPU-RS:!3819.45ND12241.91W&/A=00000070cm MMDVM Voice (C4FM) 439.55000MHz -6.0000MHz, Pi-Star_RPT
HB4A-5>APDR16,TCPIP*,qAC,T2CZECH:=RASTR RAdioSonde TRacker powered by dxlAPRS.
...
----

A full tier-2 feed carries roughly 100 frames/s (10 kB/s): capture a
minute or two, not hours. To check the dissector headlessly:

[source,console]
----
$ tshark -X lua_script:wireshark_aprsis.lua -r feed.pcap -V | grep -c "Lua Error"
0
----

== Known limitations and todo

The APRS protocol is quite complex; what is left, in rough order of
usefulness:

* Mic-E: decoded with the original APRS 1.01 destination-call table.
  The 2016 "Mic-E TOCALL" variant (explicit hemispheres, different
  message bits, aprs.org/aprs12) is not detected, so latitude
  hemisphere and message text may be wrong for modern trackers.
* Telemetry values are shown as raw numbers; the per-station PARM/
  UNIT/EQNS calibration or CCK formulas are parsed as labels but not
  applied, so there are no engineering units.
* Timestamps (DDHHMMz/h, base-91) are shown as raw strings, not
  resolved to wall-clock `FT_ABSOLUTE_TIME` fields (the year and the
  month of a base-91 stamp are genuinely ambiguous -- heuristic
  against capture time would be needed).
* Winlink/NetROM traffic sometimes embeds literal newlines in status
  text; those continuation lines appear as separate "Unknown/Other"
  APRS packets instead of being appended to the previous packet.
* Login/filter options (`filter …`, `port …`) are shown as raw text,
  not semantically parsed (APRS-IS filter language,
  https://wiki.aprs2.net/index.php?title=APRS_IS_filter_options).
* Callsigns such as `TCPIP*` or device ids like `APWW11` are not
  annotated with their meaning (see aprs-deviceid above).
* Most fields are FT_STRING for readability; only position/course/
  speed/altitude/weather numbers are typed. This keeps display simple
  but prevents range-arithmetic filters on e.g. temperatures.
* Third-party recursion has no depth limit (harmless in practice --
  servers drop loops).
* Speed: the whole TCP PDU is hex-decoded once per dissection for
  byte-accurate ranges; multi-megabyte full-feed captures dissect
  noticeably slower than a C dissector would.
* No automated regression test; validation so far is by running
  tshark -V over captures (repo `aprs-is.pcapng` and 45s full-feed
  captures from euro.aprs2.net) and asserting zero dissector errors.
  A test script over a feed corpus would be easy to add.
* Consider upstreaming as a C dissector for Wireshark (there is an
  AX.25-only `packet-aprs.c` in the C tree but no APRS-IS-over-TCP
  dissector upstream); the lua plugin remains fine for personal use.
